# 3D 테니스 게임 기획서 (수정본)

2026-10-15 기준

## 개요

1인칭 3D 테니스 게임이다. 플레이어는 위치를 잡고 공이 오기 전에 마우스 드래그로 구질을 미리 입력하며, 스윙은 공이 타격 범위에 들어오는 순간 자동으로 실행된다.

- 핵심 재미: 위치 선정과 구질 선택의 수 싸움. 스윙 타이밍은 시스템이 맞춘다
- 규칙: 실제 테니스 규칙(ITF)을 따르고, 경기 길이만 옵션으로 줄인다
- 플랫폼: PC (키보드 + 마우스)

| 모드 | 인원 | 형식 |
| --- | --- | --- |
| 싱글 | 1명 vs AI | 단식 |
| 멀티 1:1 | 2명, 온라인 | 단식 |
| 멀티 2:2 | 4명, 온라인 | 복식 |

마우스가 하나라 한 PC에서 두 명 이상 조작할 수 없으므로 멀티는 온라인 전용이다. 원안 대비 주요 변경점은 선입력 시작 시점, 이동 기준, 타격 범위 3단계, 범실 요소, 서브 조작, 발리 판정 방식이다. 문서의 수치는 모두 플레이테스트로 조정할 초기값이다.

## 시점과 카메라

카메라는 캐릭터 머리에서 공을 부드럽게 따라가고, 몸 방향과 이동 방향은 카메라와 분리한다. 1인칭은 공과의 앞뒤 거리를 판단하기 가장 어려운 시점이라, 위치 선정이 핵심인 이 게임에서는 거리감 보조가 필수다.

### 카메라 규칙

- 위치: 머리 본에 고정, 공을 향해 회전
- 몸 방향: 항상 네트를 향한다. 공을 따라 도는 건 머리(목)뿐
- 멀미 방지: 회전 속도 상한과 스무딩을 둔다. 머리 위로 넘어가는 로브처럼 크게 돌아야 할 때는 더 천천히 돈다
- 시야각(FOV): 기본 90°, 설정에서 조절

### 거리감 보조

공 그림자는 항상 보이고, 나머지 보조는 AI 난이도 쉬움(경기·랠리 연습)에서만 켜진다. 설정에서 따로 켜고 끄지 않는다.

| 요소 | 내용 | 켜지는 때 |
| --- | --- | --- |
| 공 그림자 | 공 바로 아래 진한 그림자 | 항상 |
| 낙하 지점 마커 | 상대 공이 떨어질 자리 표시 | 쉬움, 튜토리얼 |
| 타격 범위 알림 | 공이 타격 범위에 들어오면 공 테두리 강조 + 효과음 | 쉬움, 튜토리얼 |
| 자동 기본 스트로크 | 선입력이 없으면 탑스핀 스트로크를 중앙으로 자동으로 침 | 쉬움 |

튜토리얼은 표시 보조(낙하 지점 마커·타격 범위 알림)를 켜고, 선입력을 배우는 과정이라 자동 기본 스트로크는 끈다. 위치 보정(공이 가까워지면 몸을 이상적 타점 쪽으로 끌어당김), 타격 범위 링(바닥에 내 타격 범위 표시), 미니맵은 두지 않는다.

## 조작

이동은 코트 기준이다. W는 카메라가 어디를 보든 항상 네트 쪽이고, 좌클릭은 스윙이 아니라 구질 예약이다.

| 입력 | 동작 |
| --- | --- |
| W / A / S / D | 이동 (네트 쪽 / 왼쪽 / 베이스라인 쪽 / 오른쪽) |
| Shift (누르는 동안) | 달리기, 스테미너 소모 |
| 좌클릭 → 드래그 → 놓기 | 구질 선입력, 놓는 순간 확정 |
| 우클릭 | 선입력 취소 (이번 공은 치지 않음) |
| 서브 때 좌클릭 | 토스, 놓는 순간 타격 (서브 항목 참고) |

## 타격 시스템

상대가 공을 친 순간부터 구질을 미리 입력하고, 공이 타격 범위에 도착하는 시점에 맞춰 스윙이 자동으로 실행된다.

**선입력이 있고 공이 범위에 들어올 때만 스윙한다**

```mermaid
flowchart TD
    A["상대가 공을 침<br/>선입력 받기 시작"] --> B["선입력<br/>스윙 전까지 덮어쓰기"]
    B --> C["궤적 예측<br/>타점과 도착 시간"]
    C --> D{"선입력 있고<br/>스윙 범위 안?"}
    D -- 아니오 --> E["스윙 안 함<br/>공을 그냥 보냄"]
    D -- 예 --> F["스윙 시작<br/>도착 직전, 입력 잠금"]
    F --> G{"타점이<br/>타격 범위 안?"}
    G -- 예 --> H["입력 구질로 타구<br/>타구 품질만큼 오차"]
    G -- 아니오 --> I["헛스윙<br/>공은 지나감"]
    style H stroke-width:2px
```

선입력이 없거나 공이 스윙 범위 밖이면 휘두르지 않고, 휘둘렀는데 타점이 타격 범위 밖이면 헛스윙이 된다.

### 선입력

- 시작: 상대가 공을 친 순간. 시속 150km 서브는 네트에서 리시버까지 약 0.4\~0.5초라, 공이 넘어온 뒤에는 입력할 시간이 없다
- 덮어쓰기: 스윙이 시작되기 전까지 다시 입력하면 마지막 입력으로 바뀐다
- 잠금: 스윙이 시작되면 입력이 고정된다
- 입력 없음: 스윙하지 않는다. 아웃될 공을 그냥 보내는 방법이다 (우클릭으로 취소해도 같음). 단, 쉬움 난이도에서는 입력이 없으면 기본 스트로크(탑스핀, 중앙)를 자동으로 치며, 공을 보내려면 우클릭한다

### 스윙 시점

- 거리가 아니라 **임팩트까지 남은 시간**으로 정한다. 궁적을 예측해 남은 시간이 스윙 준비 시간(약 0.25초)과 같아지는 순간 스윙을 시작한다
- 거리 기준이면 빠른 공에는 늦고 느린 공에는 너무 일찍 휘두른다
- 스윙 애니메이션 재생 속도를 조절해 임팩트 순간과 공 도착 시각을 맞춘다
- 포핸드/백핸드: 예상 타점이 몸의 오른쪽이면 포핸드, 왼쪽이면 백핸드

### 타격 범위

| 구간 | 범위 (초기값) | 결과 |
| --- | --- | --- |
| 타격 범위 | 몸 중심에서 수평 1.5m 이내, 높이 0.2\~2.5m | 입력한 구질로 공을 보냄 |
| 스윙 범위 | 타격 범위 바깥 0.5m까지 | 휘두르지만 헛스윙 |
| 범위 밖 | 그 외 | 스윙하지 않음 |

높이가 달라도 범위 안이면 같은 동작으로 치고, 팔 위치는 IK로 보정한다 (애니메이션 항목).

### 타구 품질과 범실

범위 안에서 쳤다고 항상 원하는 곳으로 가지는 않는다. 아래 요소가 목표 지점의 오차를 키워 아웃과 네트가 나오고, 그래야 랠리가 끝난다.

| 요소 | 오차가 커지는 경우 |
| --- | --- |
| 타점 | 이상적 타점(허리 높이, 팔 길이 거리)에서 멀수록 |
| 이동 | 달리면서 치거나 크게 뻗어서 칠 때 |
| 스테미너 | 스테미너가 바닥일 때 |
| 상대 공 | 빠르고 스핀이 강한 공일수록 |
| 공격성 | 각도가 크고 깊고 강한 샷일수록 |

오차는 목표 지점을 원 안에서 무작위로 흔드는 방식이며, 원이 라인을 넘으면 아웃이 날 수 있다.

## 구질과 제스처

좌클릭 후 드래그 방향으로 구질을 고르고 마우스를 놓는 순간 확정한다. 가로축은 방향, 세로축은 구질로 나눠 대각선 입력은 둘의 조합으로 처리한다.

| 입력 | 결과 | 드래그 길이 |
| --- | --- | --- |
| 클릭만 | 탑스핀 스트로크, 중앙 | 없음 (베이스라인 근처로 깊게) |
| ← / → | 왼쪽 / 오른쪽으로 | 길수록 각도가 큼 |
| ↓ | 슬라이스 | 길수록 멀리, 짧으면 네트 앞 (드롭샷) |
| ↑ | 로브 (높이 띄움) | 길수록 깊게 |
| ↑ 후 ↓ | 스매시 | 높은 공일 때만 |
| ↙ ↘ ↖ ↗ | 세로축 구질 + 가로축 방향 | 축마다 따로 적용 |

### 인식 규칙

- 방향 기준: 화면이 아니라 코트 기준. ←는 상대 코트의 왼쪽 사이드라인 쪽이다
- 데드존: 화면 높이의 3% 미만 이동은 ‘클릭만’으로 처리한다. 픽셀이 아니라 비율이라 해상도와 무관하다. 데드존과 드래그 감도는 설정에서 바꾼다
- 스매시: 위로 일정 거리 이상 올린 뒤 그 지점에서 다시 일정 거리 이상 내리면 스매시. 놓기 전까지는 로브와 구분하지 않는다
- 드래그 중에는 화면에 예상 구질과 방향을 표시한다 (UI/UX 항목)

### 입력과 공이 맞지 않을 때

- 스매시 입력 + 공이 어깨 아래: 강한 플랫 스트로크로 대체
- 스매시 외 입력 + 공이 머리 위: 입력한 구질로 치되 오차 증가
- 로브 입력 + 발리 상황: 깊은 발리로 대체 (발리 항목)

## 발리와 스매시

발리는 위치만이 아니라 ‘바운드 전에 치는 공인가’로 판정한다. 위치만 보면 네트 앞에서 이미 바운드된 공도 발리 모션으로 치게 된다.

| 공 상태 | 내 위치 | 판정 |
| --- | --- | --- |
| 머리 위 + 스매시 입력 | 어디든 | 스매시 |
| 바운드 전 | 네트\~서비스라인 | 발리 |
| 바운드 전 | 서비스라인 뒤 | 발리 (오차 증가) |
| 바운드 직후 발밑 | 어디든 | 하프발리 (오차 증가) |
| 바운드 후 | 어디든 | 스트로크 |

우선순위는 스매시 > 발리 > 스트로크다.

### 바운드를 기다릴지 정하는 규칙

- 서비스라인 뒤: 공이 내 타격 범위 안에서 바운드할 예정이면 바운드를 기다려 스트로크. 바운드 지점이 내 뒤쪽 범위 밖이면 바운드 전에 발리
- 네트\~서비스라인: 바운드 전에 닿으면 항상 발리

### 발리 제스처

| 입력 | 결과 |
| --- | --- |
| 클릭만 | 기본 발리, 중앙 |
| ← / → | 왼쪽 / 오른쪽으로 |
| ↓ | 짧게 (드롭 발리), 드래그 길이와 상관없이 |
| ↑ | 깊게, 로브가 아닌 낮은 궁적 |
| ↑ 후 ↓ | 스매시 (공이 높을 때) |

## 서브

서브는 누르면 토스, 드래그로 방향과 구질, 놓는 순간이 타격 타이밍이다. 다른 샷과 달리 서브만은 타이밍을 플레이어가 직접 맞춘다.

1. 서브 위치에서 A / D로 좌우 위치 조정 (센터 마크와 사이드라인 사이)
2. 좌클릭을 누르면 토스
3. 공이 올라가는 동안 드래그로 방향과 구질 선택
4. 놓는 순간 타격. 공이 정점 부근일 때 놓으면 최대 속도와 정확도, 벗어날수록 속도가 떨어지고 오차가 커짐

| 입력 | 결과 |
| --- | --- |
| ← / → | 서비스 박스의 왼쪽 / 오른쪽 코너 |
| 세로 없음 | 플랫 서브 (빠름, 오차 큼. 머리 위 스매시와 같은 빠르기) |
| ↓ | 슬라이스 서브 (옆으로 휘어짐) |
| ↑ | 킥 서브 (높게 튀, 안정적) |

- 2서브: 속도는 1서브와 같고 오차 범위만 줄인다 (처음에는 속도도 15% 줄였다)
- 판정: 폴트, 더블폴트, 렛(네트에 맞고 서비스 박스 안에 떨어짐)
- 풋폴트는 없다. 서브 위치를 베이스라인 뒤로 고정하기 때문이다

## 이동과 스테미너

걷기만으로 대부분의 공에 닿고, 달리기는 크게 빠진 공을 따라잡을 때 한 번 쓰는 용도다. 원안의 ‘중앙에서 양쪽 끝까지’는 중앙에서 한쪽 사이드라인까지 한 번으로 확정했다.

| 항목 | 초기값 |
| --- | --- |
| 걷기 속도 | 4 m/s |
| 달리기 속도 | 10 m/s (처음 7, 플레이테스트로 올림. AI는 쉬움 6·보통 8·어려움 10) |
| 가득 찬 스테미너로 달릴 수 있는 거리 | 약 5m (단식 중앙→사이드라인 4.1m + 여유). 코트 너비 배율만큼 늘어남 |
| 회복 | 걷거나 멈춰 있을 때 초당 30% |
| 포인트 사이 | 전부 회복 |
| 바닥났을 때 | 50% 회복 전까지 달리기 불가 |

- 스테미너가 낮으면 타구 오차가 커진다 (타격 시스템 항목)
- 회복에 약 3초가 걸려, 연속으로 크게 빠지는 공 두 개는 둘 다 달려서 따라갈 수 없다
- 달릴 수 있는 거리는 '중앙→한쪽 사이드라인' 기준이라, 코트 너비를 바꾸면 같이 늘어난다
- 현실처럼 뒷걸음(자기 베이스라인 쪽)은 느리다: 앞·옆 속도의 60%, 대각선 뒤는 그 사이. AI도 같고, 제때 닿을지 판단할 때도 이 속도로 본다. 네트 앞에서 로브를 쫓아 물러날 때, 깊은 로브는 걸어서는 늦고 달려야 닿는다
- 속도 스탯이 걷기·달리기 속도와 회복을, 코트 바닥이 출발·제동을 바꾼다 (클레이는 멈출 때 미끄러짐). 현실의 클레이 강자처럼 속도 스탯이 높으면 덜 미끄러진다
- AI도 같은 규칙을 쓴다. 걸어서도 제때 닿으면 걸어서 스테미너를 아낀다
- 달릴 때 자세: 오른손은 그립, 왼손은 넥을 잡는다

## 선수와 스탯

플레이어는 프리셋 캐릭터 중 하나를 고른다. 스탯은 0\~100(기준 50)이고 캐릭터마다 고정이라 직접 배분하지 않으며, 같은 캐릭터를 여러 명이 동시에 고를 수 있다.

| 스탯 | 올라가면 | 스탯 100일 때 (기준 50 대비, 0이면 반대) | 연결 항목 |
| --- | --- | --- | --- |
| 힘 | 스트로크·발리·스매시·서브가 빨라진다 | 속도 +10% | 샷 속도, 서브 |
| 기술 | 타구 오차가 줄고 스핀이 늘며, 코너를 사이드라인 더 가까이 노린다 | 오차 −40%, 스핀 +25%, 사이드라인 여유 −80% | 타구 품질과 범실 |
| 속도 | 걷기·달리기가 빨라지고 스테미너가 빨리 회복되며, 클레이·잔디에서 멈출 때 덜 미끄러진다 | 이동 +10%, 회복 +25%, 미끄러짐 −50% | 이동과 스테미너 |

### 로스터

| 유형 | 힘 | 기술 | 속도 | 합계 | 성격 |
| --- | --- | --- | --- | --- | --- |
| 균형형 | 50 | 50 | 50 | 150 | 입문용, 약점 없음 |
| 공격형 | 80 | 40 | 30 | 150 | 공과 서브가 가장 빠름, 발이 느리고 쉽게 지침 |
| 컨트롤형 | 30 | 80 | 40 | 150 | 오차 작고 스핀 강함, 코너를 라인 가까이 노림 |
| 수비형 | 30 | 40 | 80 | 150 | 가장 빠르고 회복이 빨라 넓게 수비 |

- 모든 캐릭터는 오른손잡이, 양손 백핸드다. 왼손잡이와 한손 백핸드는 만들지 않는다
- 같은 캐릭터 중복 선택은 같은 팀, 상대 팀 모두 허용한다
- 효과 폭은 스탯마다 다르다. 기술의 오차 효과(±40%)를 가장 넓게 둔다. 이동 효과는 처음에 ±6%로 가장 좁게 뒀지만, 플레이해 보니 좌우로 번갈아 오는 공을 속도 스탯으로도 따라잡지 못해 ±15%로 넓혔다가 공격형 대 수비형 측정 뒤 ±10%(1포인트당 0.2%)로 맞췄다
- 스탯은 모두 장점만 있고, 대가는 합계 안에서 다른 스탯을 포기하는 것이다. 예전에는 힘으로 빨라진 만큼 타구 품질 벌점(범실)이 붙었지만, 힘만 대가를 두 번 내는 구조라 없앴다
- AI도 프리셋 캐릭터 중 하나를 쓰고 성향을 유형에 맞춘다: 공격형은 슬라이스·로브·드롭샷을 덜 치고 첫 서브를 플랫으로 더 넣고, 컨트롤형은 드롭샷·슬라이스를 조금 더, 수비형은 몰렸을 때 슬라이스·로브를 조금 더 쓰고 첫 서브를 안전하게 넣는다
- 밸런스: 합계 150에서 시작해 AI끼리 자동 대전(AI 대결 관전)으로 조합별 포인트 승률을 재고 45\~55%가 되도록 조정한다. 측정해 보니 승부는 주로 공에 못 닿아서 갈려, 오차보다 공 속도·이동이 크게 작용했다. 그래서 기술에 '라인 가까이 노리기'를 더했다. 수비형은 이동 효과가 ±6%일 때 170으로 보강했다가, 이동 효과를 넓히면서 150으로 되돌렸다
- 최근 측정(2026-10-16, 코트 너비 2배·공 지름 0.3m·공 템포 0.8 실험 설정, 보통 난이도): 이동 ±10%·덜 미끄러짐·힘 벌점 제거·플랫 서브 51 m/s·2서브 감속 제거 뒤 6개 조합을 세 코트에서 쟀다. 18개 중 4개가 45\~55% 밖이다 (공격형이 균형형에게 하드 56.2%·잔디 55.3%, 수비형에게 하드 55.9%, 균형형이 수비형에게 클레이 56.3%). 선수별 평균 포인트 승률은 공격형 53.2%, 균형형 49.5%, 컨트롤형 48.9%, 수비형 48.4%로 힘 벌점을 없앤 공격형이 조금 강했다. 그래서 힘 효과를 +6.5%에서 +5%로 줄이고 공격형 조합만 다시 쟀다: 공격형 평균 51.4% (하드 52.0, 클레이 51.5, 잔디 50.5), 9개 중 공격형 대 컨트롤형 하드 55.0%·잔디 55.3%가 경계에 걸린다
- 조합당 320포인트라 같은 설정도 다시 재면 ±5%쯤 흔들린다 (바뀐 게 없는 하드에서 균형형 대 수비형 53.8% → 46.3%). 한 조합 결과보다 선수별 평균(9개 조합)을 본다. 최종 코트·공 크기를 정하면 또 잰다
- 어려움 난이도 측정(2026-10-19, 하드, 달리기 플레이어 10 m/s·AI 쉬움 6·보통 8·어려움 10 m/s): 선수별 평균 균형형 53.2%, 컨트롤형 52.5%, 수비형 48.9%, 공격형 45.4%. 공격형 대 컨트롤형 43.8%가 범위 밖이라 힘 효과를 +5%에서 +10%(1포인트당 0.2%)로 올렸다. 공격형 조합만 다시 재니 공격형 평균 49.2% (컨트롤형에게 50.3%, 수비형에게 52.5%, 균형형에게 44.7%)

## 코트와 공 물리

코트는 클레이, 잔디, 하드 세 종류이며 바운드 높이, 바운드 후 속도, 스핀 효과, 선수 이동감이 다르다. 원안의 ‘모래’ 코트는 클레이로 확정했고, ‘우레탄’은 하드 코트다.

| 특성 | 클레이 | 잔디 | 하드 (우레탄) |
| --- | --- | --- | --- |
| 바운드 높이 | 높음 | 낮음 | 중간 |
| 바운드 후 속도 | 많이 느려짐 | 거의 유지, 미끄러지듯 | 중간 |
| 스핀 효과 | 강함, 탑스핀이 높게 튀 | 슬라이스가 낮게 깔림 | 보통 |
| 선수 이동 | 멈출 때 미끄러짐 | 미끄러움 | 기본 |
| 특징 | 공 자국이 남아 인·아웃 확인 | 가장 빠른 랠리 | 기준 코트 |

구현한 값은 아래와 같고 모두 Inspector에서 조절한다. 클레이에서는 공이 떨어진 자리에 진행 방향으로 길쭉한 자국이 남고 다음 포인트에 지워진다.

| 값 | 하드 | 클레이 | 잔디 |
| --- | --- | --- | --- |
| 반발 (바운드 높이) | 0.73 | 0.82 | 0.62 |
| 마찰 (감속·스핀 반응) | 0.55 | 0.90 | 0.30 |
| 바운드 뒤 수평 속도 유지 | 100% | 90% | 100% |
| 출발 가속 / 멈출 때 제동 | 100% / 100% | 90% / 45% | 75% / 60% |
| 탑스핀 드라이브 바운드 높이 | 0.81m | 1.01m | 0.58m |

### 공 물리 모델

- 비행: 중력 + 공기저항 + 스핀에 의한 휘어짐(마그누스 효과)
- 바운드: 코트별 반발 계수(바운드 높이)와 마찰 계수(속도 감소, 스핀 반응)
- 네트: 상단에 맞으면 속도가 줄고 넘어가거나 떨어진다
- 같은 입력이면 항상 같은 궁적이 나오도록 직접 계산한다. 자동 스윙·AI·낙하 마커의 궁적 예측과 멀티 동기화에 필요하다 (구현 메모)

## 규칙과 경기 형식

실제 테니스 규칙(ITF)을 따르되, 3세트 경기는 게임으로 너무 길어 경기 길이를 옵션으로 고르게 한다.

| 옵션 | 내용 |
| --- | --- |
| 타이브레이크 | 7점 선취, 2점 차 |
| 단축 세트 | 4게임 선취, 4:4에서 타이브레이크 |
| 1세트 | 6게임 선취, 6:6에서 타이브레이크 |
| 3세트 | 2세트 선취 (실제 규칙) |
| 노애드 (추가 옵션) | 듀스에서 다음 1점으로 게임 결정 |

### 적용 규칙

- 점수: 15·30·40, 듀스·어드밴티지, 세트, 타이브레이크
- 서브: 대각선 서비스 박스, 듀스 코트·애드 코트 교대, 폴트·더블폴트·렛
- 실점: 아웃, 네트, 투바운드, 몸에 맞은 공, 라켓이나 몸이 네트에 닿음
- 엔드 체인지: 홀수 게임이 끝난 뒤, 타이브레이크는 6점마다
- 제외: 풋폴트 (서브 위치 고정)

### 포인트 사이

- 포인트가 끝나고 2초 뒤 모든 선수를 정해진 위치로 자동 이동한다. 1인칭에서 걸어서 돌아가는 시간을 없앤다
- 판정 리플레이는 두지 않는다

## 복식

복식은 실제 규칙대로 서브·리시브 순서를 따르고, 같은 팀 두 명이 한 공을 동시에 치지 않도록 한 명만 스윙하게 한다.

- 서브 순서: A팀 1번 → B팀 1번 → A팀 2번 → B팀 2번. 세트가 바뀔 때 팀 안에서 순서를 바꿀 수 있다
- 리시브: 세트 시작 때 정한 듀스 코트·애드 코트 담당을 세트가 끝날 때까지 유지한다
- 스윙 충돌: 둘 다 선입력했다면 예상 타점이 더 가까운 선수만 스윙하고, 다른 선수의 입력은 취소한다. 거리가 같으면 포핸드 쪽 선수가 친다
- 캐릭터 충돌: 팀원끼리 겹치지 않게 밀어내기만 하고, 넘어지거나 실점하지 않는다
- 포인트 시작 위치: 서버의 파트너는 네트 앞, 리시버의 파트너는 서비스라인 근처에 자동 배치

## AI

AI는 플레이어와 같은 물리, 타격 범위, 오차 규칙, 스테미너를 쓰고, 난이도는 반응 속도·정확도·위치 선정·구질 선택으로 나눈다.

| 난이도 | 반응 지연 | 타구 오차 | 위치 선정 | 구질 선택 | 네트 대시 / 서브 앤 발리 |
| --- | --- | --- | --- | --- | --- |
| 쉬움 | 0.4초 | 큼 | 공을 늦게 따라가고 친 뒤 천천히 가운데로 복귀 | 탑스핀 위주, 방향은 대체로 무작위 | 없음 |
| 보통 | 0.25초 | 보통 | 친 뒤 가운데 복귀, 보낸 공 쪽으로 조금 치우침 | 상황에 맞춰 슬라이스·로브·드롭샷 | 10% / 5% |
| 어려움 | 0.12초 | 작음 | 보낸 공 쪽으로 치우쳐 상대 각도의 가운데를 선점 | 빈 곳 공략 | 30% / 12% |

- 반응 지연: 상대가 친 뒤 AI가 움직이기 시작할 때까지 걸리는 시간 (초기값)
- 쉬움에서는 플레이어 쪽 보조(낙하 지점 마커·타격 범위 알림·자동 기본 스트로크)가 켜진다 (거리감 보조 항목)
- 스테미너: 플레이어와 같은 규칙. 걸어서도 제때 닿으면 걷고, 지치면 걷기 속도로 떨어지고 타구가 흔들린다
- 샷 선택: 평범한 랠리는 탑스핀 위주. 겨우 닿는 공이면 높은 로브나 낮은 슬라이스로 버티고, 베이스라인 안쪽 짧은 공에 상대가 뒤에 있으면 드롭샷, 상대가 네트에 있으면 패싱샷이나 로브, 높이 뜬 공은 스매시
- 네트 대시: 베이스라인 안쪽에서 친 뒤나 서브 직후 확률로 네트에 들어가 발리한다. 네트 앞 자리까지 못 가면 서비스라인 안쪽에서라도 발리한다
- 코트별 성향: 클레이에서는 베이스라인 랠리와 로브·드롭샷, 잔디에서는 서브 앤 발리·네트 대시와 낮은 슬라이스가 늘어난다
- AI 대결 관전: 메뉴에서 AI끼리 경기를 볼 수 있고, 같은 기능으로 캐릭터 밸런스를 재다 (선수와 스탯 항목)
- 복식 AI: 멀티에서 빈자리를 채우거나 접속이 끊긴 선수를 대신한다. 파트너와 역할을 나눠(한 명은 네트 앞, 한 명은 베이스라인) 위치를 잡고, 복식 스윙 충돌 규칙을 따른다

## 멀티플레이

멀티는 온라인 1:1과 2:2만 제공한다. 공 궁적을 항상 같은 결과로 계산하므로, 공 위치를 매 프레임 보내지 않고 ‘타격 순간 정보’만 주고받는다.

| 항목 | 방식 |
| --- | --- |
| 동기화 대상 | 선수 위치·애니메이션 상태, 타격 이벤트(공 위치·속도·스핀·시각) |
| 공 비행 | 타격 이벤트를 받은 각 클라이언트가 같은 계산으로 재현 |
| 타격 판정 | 공을 치는 선수의 클라이언트가 판정, 호스트가 검증 |
| 점수·인아웃 | 호스트가 최종 결정 |
| 매칭 | 방 코드로 친구 초대 + 빠른 매칭. 인원이 모자라면 빈자리를 AI로 채움 (예: 2:2에서 3명 + AI 1명) |
| 접속 끊김 | 30초 재접속 대기, 이후 AI가 대신 플레이. 패배 처리하지 않고, 재접속하면 다음 포인트부터 조작을 돌려받는다 |

타격 판정을 치는 사람 쪽에 맡기는 이유는 자동 스윙 타이밍이 핑(지연) 때문에 어긋나지 않게 하기 위해서다.

### 추가로 필요한 동작

| 분류 | 동작 |

| 이동 | 준비 자세, 걷기, 달리기(오른손 그립·왼손 넥), 옆걸음, 뒷걸음, 스플릿 스텝, 급정지 |

헛스윙은 해당 타격 동작을 그대로 재사용한다.

### 현재 상태 (임시 동작)

- 모션캡처 전 임시로 7종을 Blender 스크립트(`ArtSource/Blender/tennis_animations.py`)로 손으로 짰다: 준비 자세, 포핸드, 양손 백핸드, 서브, 스매시, 포·백 발리. 슬라이스·로브는 스트로크 동작을 같이 쓴다
- 포·백핸드 핵심 자세는 프로 선수 슬로모션 영상(조코비치·페더러·디미트로프 포핸드, 조코비치 양손 백핸드)을 프레임으로 끊어 맞췄다: 몸 돌리기 때 팔꿈치를 굽혀 라켓을 어깨 높이에 세우고 왼팔은 공 쪽으로 뻗는다, 드롭 때 라켓이 엉덩이 아래로 떨어지며 무릎이 가장 깊게 굽는다, 마무리는 머리 위가 아니라 반대쪽 어깨를 감싼다
- 핵심 자세 몇 개를 정하고 팔·다리는 IK로 잡은 뒤 매 프레임으로 굽는다
  - 그립: 손목을 펴면 라켓이 아래팔과 직각(ㄴ자)이 되게 손잡이가 손바닥을 가로지른다 (영상의 컨티넨탈·이스턴 그립 모양)
  - 손목: 비틀림은 아래팔과 나누고, 꺾임은 50도(양손 그립의 왼손 70도)까지. 더 꺾여야 하는 자세는 라켓 방향을 팔에 맞춘다
  - 팔꿈치 방향: 손목이 곧은 쪽과 자세마다 정한 방향(대개 아래·앞)을 4:6으로 섞는다. 손목만 보고 고르면 팔꿈치가 들려 어깨가 과하게 돈다
  - 위팔·아래팔의 굽힘 축을 어깨-팔꿈치-손목 평면에 맞춘다. IK가 위팔을 아무렇게나 돌려 팔꿈치가 반대로 굽은 것처럼 어깨가 꼬이던 것을 고쳤다
- 라켓은 오른손에 고정된다. 리그에 손가락 뼈가 없어 손 쥐기는 블렌드셰이프(GripR·GripL)로 한다: 오른손은 늘 쥐고, 왼손은 라켓 목·양손 그립 구간에서만 쥔다. 양손 백핸드의 왼손은 매 프레임 실제 라켓 위치로 다시 잡는다
- 공 위치 보정: 클립마다 임팩트 프레임의 라켓 타구점(골반 기준)을 재 두고, 실제 타점과의 차이만큼 임팩트 0.3초 전부터 오른팔을 IK로 당긴다 (손 방향 = 라켓 각도는 그대로). 팔이 모자란 거리는 몸을 수평으로 최대 35cm 옮기고, 양손 그립이면 왼손도 같이 옮긴다. AI 대결 20번 스윙에서 임팩트 때 라켓 타구점과 공 중심 거리가 평균 26cm → 13cm, 최대 89cm → 35cm로 줄었다 (공 반지름 15cm)
- 낮은 공: 모자란 높이의 70%를 몸을 낮춰(최대 30cm) 메우고, 나머지는 손목을 축으로 라켓 헤드를 떨어뜨린다(최대 55도). 몸을 옮기거나 낮춰도 발은 그 자리에 두고 다리 IK로 무릎을 굽힌다. 45cm까지 낮추면 깊게 쪼그려 앉는 자세가 어색해서 30cm로 줄였다. 선 채로 친 시험에서 포핸드 타점 높이 0.6m·0.35m·0.2m의 라켓-공 거리가 0·6·16cm, 백핸드 0.5m·0.3m가 11·24cm (몸 낮추기 전 포핸드 7·20·30cm)
- 게임에서는 공이 오는 만큼 테이크백하고, 스윙은 클립의 임팩트 프레임이 공 도착 시각에 오게 빨리 돌린다. 서브는 토스하는 동안 트로피 자세에서 기다린다
- 서 있으면 온몸 스윙, 이동 중이면 상체만 스윙하고 다리는 걷기·달리기. 빠르게 옆으로 달릴 때는 몸을 이동 방향으로 돌린다 (옆걸음·뒷걸음 동작이 아직 없어서)
- 1인칭 화면에는 아직 팔이 보이지 않는다. 몸은 그림자만 남기고 라켓만 보인다

### 1인칭 처리

- 본인 화면에는 팔과 라켓만 보이고, 전신 동작은 상대와 파트너에게만 보인다
- 전신 애니메이션 한 세트만 만들고 카메라를 머리 본에 붙인다. 1인칭용 팔 애니메이션은 따로 만들지 않는다
- 모든 캐릭터가 오른손잡이·양손 백핸드라 타격 애니메이션 한 세트를 전원이 공유한다

## UI/UX

화면에는 점수, 스테미너, 현재 선입력, 방금 친 공의 타구 품질만 최소한으로 표시한다. 거리감 보조 요소는 시점과 카메라 항목에 있다.

| 요소 | 위치 | 내용 |
| --- | --- | --- |
| 점수판 | 화면 위 | 세트·게임·포인트, 서버 표시, 코트와 선수 유형 |
| 스테미너 바 | 화면 아래 | 바닥나면 붉게 표시 |
| 선입력 표시 | 화면 중앙 아래 | 구질 아이콘 + 방향 화살표, 드래그 중에는 예상 구질 미리보기 |
| 타구 품질 | 화면 중앙 아래 | 칠 때마다 좋음·보통·나쁨과 큰 원인 두 개 (타점 높음, 방향을 크게 줌, 뛰면서 침 등) |
| 시작 메뉴 | 전체 화면 | 모드(경기·랠리 연습·튜토리얼·AI 대결 관전), 경기 방식, 코트, 난이도, 내 선수·상대 선수, 설정 |

- 튜토리얼: 이동 → 선입력 → 구질 5종 → 발리 → 서브 순서로 단계별 연습 (아래 표)
- 설정: 시작 메뉴와 일시정지 메뉴에서 연다. 값은 이 PC에 저장되어 다음 실행에도 유지된다

| 항목 | 범위 (기본) | 내용 |
| --- | --- | --- |
| 드래그 감도 | 0.5\~2배 (1배) | 드래그 길이에 곱한다. 카메라는 공을 자동으로 따라가서 마우스는 구질 드래그에만 쓴다 |
| 드래그 데드존 | 화면 높이 1\~5% (3%) | 좌우로 이보다 짧게 끌면 가운데로 친다 |
| 카메라 회전 속도 | 0.5\~2배 (1배) | 공을 따라 고개를 돌리는 빠르기. 느릴수록 멀미가 덜하다 |
| 시야각 | 50\~110° (75°) | 플레이 중 [ ] 키로도 바꾼다 |

설정 화면 아래 연습 칸에서 드래그해 보면 지금 설정으로 나오는 구질과 방향을 바로 보여 준다.

### 튜토리얼

시작 메뉴의 모드에서 고른다. 과제를 하나씩 주고, 성공하면 다음 과제로 넘어간다. 상대 AI는 정해진 공을 주기만 하고 받아치지 않으며, 판정은 과제별로 한다: 친 공이 상대 코트에 들어갔고 과제가 원하는 샷인지.

| 단계 | 과제 | 성공 조건 |
| --- | --- | --- |
| 1 이동 | WASD로 초록 원 3개, Shift로 달려서 먼 원 1개 | 원 안에 들어감 (달리기 과제는 가는 동안 달려야 함) |
| 2 선입력 | 상대가 친 뒤 좌클릭해서 받아넘기기 ×2, 예약 뒤 우클릭으로 공 보내기 | 넣기 / 우클릭으로 보냄 |
| 3 구질 5종 | 탑스핀(클릭), ← 왼쪽, → 오른쪽, ↓ 슬라이스, ↓ 짧게 드롭샷, ↑ 로브, ↑↓ 스매시 | 그 구질로 넣기 (스매시는 머리 위 타점, AI가 로브를 줌) |
| 4 발리 | 네트 앞에서 바운드 전에 받아넘기기 ×2, ↓ 드롭 발리 | 발리로 넣기 |
| 5 서브 | 서브 넣기 ×2, 슬라이스·킥 서브 넣기 | 서비스 박스에 넣기 (렛은 다시) |

- 보조: 튜토리얼 동안 낙하 지점 마커·타격 범위 알림을 켜고, 자동 기본 스트로크는 끈다 (선입력을 배우는 과정이라서)
- 이동 과제 동안 카메라는 공 대신 목표 원을 본다
- 실패하면 원인을 한 줄로 알려 준다: 아웃·네트, 입력 없음, 헛스윙, 다른 구질로 침 등
- 일시정지(Esc) 메뉴에서 지금 과제를 건너뛸 수 있다. 다 마치면 처음부터 · 랠리 연습 · 메뉴로를 고른다

## 구현 메모 (Unity)

공 물리와 타격은 Unity 물리 엔진에 맡기지 않고 직접 계산하는 것이 핵심이다. 그래야 궁적 예측, AI, 멀티 동기화가 모두 같은 계산을 공유한다.

| 영역 | 방식 |
| --- | --- |
| 공 | Rigidbody 대신 FixedUpdate에서 직접 계산 (중력, 공기저항, 마그누스). 빠른 공이 콜라이더를 뚫는 문제와 결과가 매번 달라지는 문제를 피한다 |
| 타격 | 라켓 콜라이더 충돌을 쓰지 않는다. 임팩트 프레임(Animation Event)에서 목표 지점에 떨어지는 초기 속도를 역산해 부여하고, 오차는 목표 지점을 흔들어 적용 |
| 궁적 예측 | 같은 물리 함수를 미리 돌려 낙하 지점·타점·도착 시간 계산. 자동 스윙, AI, 낙하 마커가 공유 |
| 스윙 타이밍 | Animator 재생 속도를 조절해 임팩트 프레임을 공 도착 시각에 맞춤 |
| 높이 보정 | Animation Rigging 패키지의 Two Bone IK |
| 카메라 | Cinemachine으로 공 추적, 회전 속도 제한. 머리 본의 위치만 따라가고(스윙 때 흔들림은 위치 스무딩), 회전은 공 추적이 정한다. 내 캐릭터의 머리 메시는 내 화면에서만 숨긴다. 비교 테스트용 3인칭 디버그 카메라 포함 |
| 입력 | Input System 패키지로 드래그 제스처 인식 |
| 네트워크 | Netcode for GameObjects + Unity Multiplayer Services(Sessions: Lobby·Relay·Matchmaker). 공 궁적을 같은 계산으로 재현하므로 예측·롤백 없이 시작하고, 다른 선수의 움직임은 NetworkTransform 보간으로 부드럽게 처리 |

## 개발 단계와 미결정 사항

가장 큰 위험은 ‘선입력 + 자동 스윙’이 실제로 재미있는가이므로, 코트 하나와 기본 구질만으로 먼저 검증한 뒤 콘텐츠와 온라인으로 넓힌다.

진행 (2026-10-19 기준): 1·2단계를 마쳤다. 3단계는 클레이·잔디 코트, 프리셋 캐릭터·스탯, AI 다듬기(스테미너·네트 대시·코트별 성향·AI 대결 관전)와 캐릭터 밸런스, 선수 모델과 임시 애니메이션 연결, 튜토리얼까지 했다. 남은 것은 애니메이션 보강(1인칭 팔, 옆걸음·뒷걸음)이다.
